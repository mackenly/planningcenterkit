Planning Center Kit covers all 11 Planning Center products. Each one is a property on
`PlanningCenter`, a standalone client from its own subpath import, and a namespace of types.

```ts
import { PlanningCenter } from '@mackenly/planningcenterkit';

const pco = new PlanningCenter({ auth: { applicationId: '...', secret: '...' } });
await pco.checkIns.check_ins.order('-created_at').first();
```

```ts
import { createCheckInsClient } from '@mackenly/planningcenterkit/check-ins';

const checkIns = createCheckInsClient({ auth: { applicationId: '...', secret: '...' } });
await checkIns.check_ins.order('-created_at').first();
```

Standalone clients take the same options as `PlanningCenter` plus `version`, or an existing
`transport` to share rate limiting and credentials (see
[Errors and retries](/guides/errors-and-retries/#rate-limiting)).

**Webhooks naming:** `pco.webhooks` and `@mackenly/planningcenterkit/webhooks-api` are the
*Webhooks product API* (subscriptions, available events, deliveries).
`@mackenly/planningcenterkit/webhooks` is for *receiving* webhooks (signature verification and
parsing); see [Webhooks](/guides/webhooks/).

**API versions:** each product is pinned to the version of Planning Center's documentation its
types were generated from, sent as `X-PCO-API-Version`. Override with
`new PlanningCenter({ auth, versions: { checkIns: '2025-01-01' } })` or
`createCheckInsClient({ auth, version: '2025-01-01' })`; the types won't follow an override.

The [reference](/reference/) has a page per product and per resource with every client path,
attribute, and query option.

**Root collections** are the properties on each product client, named after their URL
(`pco.people.people` is `/people/v2/people`). "(create)" marks the ones you can `create()` on.
Every client also has `get()` for the product root (usually the organization) and `edge(name)`.

| Pinned API version | `2026-09-24` |
| Resource types | 7 |
