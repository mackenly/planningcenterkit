# Working on Planning Center Kit

Instructions for agents (and people) changing this repository. To *use* the library, read
[llms.txt](llms.txt) or https://planningcenterkit.mackenly.com instead.

## Layout

- `src/core/`: hand-written runtime: transport (`http.ts`), auth and OAuth, the query builder (`query.ts`, `product.ts`), errors, and the contracts the generated code satisfies (`graph.ts`, `jsonapi.ts`, `transport.ts`).
- `src/generated/`: **generated, never edit by hand.** Produced by `scripts/generate.ts` from `spec/`.
- `spec/`: snapshot of Planning Center's documentation JSON, written by `scripts/fetch-spec.ts`. Refreshed weekly by CI.
- `src/webhooks/`: receiving webhooks. `src/entries/`: subpath entry points (`@mackenly/planningcenterkit/<name>`).
- `site/`: the Nimbus docs site (its own package). Reference pages are generated by `scripts/generate-reference.ts`.
- `test/`: vitest; `*.test-d.ts` files are type tests.

## Commands

```sh
npm run check          # typecheck + tests + build; run before finishing any change
npm run spec:fetch     # re-download Planning Center's docs into spec/
npm run generate       # spec/ -> src/generated/ (deterministic)
npm run spec:diff      # semver impact of spec/ changes vs HEAD
npm run docs:dev       # docs site locally
```

## Rules

- Zero runtime dependencies. No `node:*` imports in `src/` (it must run on Workers, Deno, Bun, browsers).
- ESM source: relative imports end in `.js`; use `import type` for types. Scripts run with Node type stripping, so only erasable TypeScript syntax there.
- Change generated output by changing `scripts/generate.ts` (or the contracts in `src/core/graph.ts`), then run `npm run generate`. Never edit `src/generated/` directly.
- API names stay snake_case exactly as in Planning Center's docs; only product properties are camelCase.
- Every public export gets TSDoc with an example that compiles against the real generated names.
- Add tests for behavior changes; risky logic (retries, auth refresh, URL building, webhook verification) needs regression tests that fail without the fix.
- Releases are automatic; see [RELEASING.md](RELEASING.md). Use `feat:` (or `feat(scope):`) for minor and `BREAKING CHANGE` or `bump-major` for major bumps in commit messages.
